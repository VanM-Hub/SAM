## 2. Jalur Registrasi Canonical (pola bootstrap sbg template yang BENAR)

```
WardIdentity.new(ward_type, name, seed)          # ward_id deterministik
  → WardOwner(owner_id=tenant_username, ...)      # owner = AUTHENTICATED session, bukan input bebas
  → WardAccessScope(scope, resource, endpoints)
  → WardMetadata(description, ...)
  → Entrustment(ward_id, owner_id, allowed_capabilities, access_scope, approval_policy)
  → manager.register_ward(identity, owner=..., access_scope=..., metadata=..., entrustment=...)
      → repository.register(...) → _persist()      # PostgreSQL (postgres store)
  → return ward_id
```

**PERSIST + REHYDRATE:** `WardRepository(store)` → `_recover_from_store()` di `__init__` memuat ulang `wards` + `entrustments` dari store. Jadi restart → rehydrate sudah teruji oleh desain (W1 accept F).

## 4. Desain REST Boundary yang Benar (per Van — bukan shortcut)

- Route baru `WardsRoutes` (mirip pola `ux.py`/`citizens.py`) di `src/sam/api/routes/`.
- Endpoint `POST /wards` (register) + `GET /wards`, `GET /wards/{ward_id}` (list/detail) — minimal utk W2.5.
- **Tenant/owner TIDAK dari input UI**: dari `self.sessions.authenticate(token)` (UxRoutes L250-267) → `{'username','role'}` → `WardOwner(owner_id=username)` + `Entrustment(owner_id=username)`.
- **Auth**: wajibkan identity saat AUTH aktif (`SAM_ENABLE_AUTH=1`), pola sama dgn ux (login → token bearer). Bila auth off (dev), pakai tenant default "user" — namun owner harus TETAP dari session, bukan input.
- **Tidak hardcode OpenClaw**: resource/type/name dari modal UI, bukan substitution.
- **`manager.with_tenant({'username': username, 'role': role})`** untuk bind tenant per-request sebelum register (agar ownership benar).
