## 3. Analisis (Temuan berbasis bukti)

### 3.1 G1-03 — `docs\core\` (EXECUTION_MODEL & THINKING_PROTOCOL)

| # | Temuan | Severity | Detail |
|---|---|---|---|
| T1 | **Dua file berstatus Draft, bukan canonical** | Medium | Draft v0.1.0, 2026-07-20, gaya generik |
| T2 | **Tidak tercantum di ATLAS** | Medium | tidak termasuk navigasi resmi |
| T3 | **Menduplikasi authority Execution** | High | dgn `EXECUTION_SPECIFICATION.md` (v1.0 Foundational) — AI-002 (audit) |
| T4 | **Referensi eksplisit dari 8 file (16 ref), termasuk spec freeze** | High | relokasi = putus dependency sah |
| T5 | THINKING_PROTOCOL merujuk model (`docs\models\`) yang lokasinya beda | Medium | `DECISION_MODEL` dll ada di `docs\models\`, bukan `docs\core\` |

**Rekomendasi (menunggu keputusan):**
- **Opsi A (in-place, tanpa pindah):** tandai kedua file sebagai **Reference/Draft** (tanpa ubah isi), pertahankan
  path → 16 referensi tetap valid. Risiko paling rendah, reversible.
- **Opsi B (relokasi):** pindah ke `docs\history\` (arsip) ATAU `docs\models\` → **wajib update 16 referensi di 8 file**
  + spec freeze. Risiko memutus referensi bila tidak tuntas. Butuh persetujuan update lintas file.
- **Opsi C (konsolidasi):** hapus EXECUTION_MODEL, jadikan `EXECUTION_SPECIFICATION` satu-satunya authority →
  perubahan lebih luas, perlu sinkronisasi.

**Keputusan yang diminta:** opsi mana (A/B/C) untuk klasifikasi `docs\core\` — dan apakah relokasi (B) boleh
dilakukan Engineering dengan wewenang update referensi lintas file.
